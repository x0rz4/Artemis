# Artemis 统一风格规范

本文件集中维护代码、UI、产品命名、文案与文档风格。AGENTS.md、CLAUDE.md 和能力 SPEC 只引用它，不另建风格副本。特定功能的行为写入能力 SPEC，开发步骤见 [WORKFLOW.md](WORKFLOW.md)。

## 产品命名与术语

- 对外产品名统一为 **Artemis**，可执行文件为 `artemis.exe` / `artemis`，页面品牌、日志、导出文件名保持一致。
- 项目基于 ARTEX；Go module/import `github.com/Autumn-27/artex` 和 `ARTEX_*` 环境变量保留内部兼容名称，不因品牌统一而批量替换。来源与版权说明保留原名。
- 品牌串维护位置：`web/src/config/app-config.ts`、登录/初始化页、侧边栏、`cmd/artex/main.go` 的 banner 与日志。二进制与包名位置：`build.bat`、`build.sh`、`start.bat`、`start.sh`、`Dockerfile`、`scripts/package-release.ps1`。
- 界面默认使用简体中文，同一概念沿用已有术语与导航名称；API、Agent、Skill、MCP 等技术标识按已有上下文使用，不随意混换名称。

## 代码与文件

- 修改遵循所在模块结构，保持改动范围清晰；复用已有组件、工具函数和错误处理方式。避免为风格统一重写无关代码。
- Go 使用 `gofmt`；包名、导出名、缩写及测试命名遵循相邻代码。错误应提供必要上下文，不忽略会影响行为的错误；注释解释约束与原因。
- 前端格式和检查以 [biome.json](../web/biome.json) 为准，类型约束以 [tsconfig.json](../web/tsconfig.json) 为准。不要另引入相互冲突的格式化配置，也不为消除错误宽泛关闭规则。
- React 组件名使用 PascalCase，Hook 使用 `use` 前缀，普通变量和函数用 camelCase；普通前端文件使用 kebab-case，Next.js 特殊文件名遵循框架约定。
- 前端优先使用已有 `@/` 路径别名和共享类型；API 及数据结构入口见 PROJECT.md。异步操作明确处理加载、成功和失败，避免无说明的 `any`、断言或静默吞错。
- 工具排除目录不做顺手全量格式化；必要修改保持该文件既有风格。跨平台脚本遵循 [.gitattributes](../.gitattributes)，文档使用 UTF-8。

## 界面与交互

- 延续现有页面布局与信息密度，优先复用 `web/src/components/ui/` 的组件、已有表格、表单和弹窗模式。新增页面先参照同类业务页。
- 色彩、背景、边框、圆角和字体优先使用 [globals.css](../web/src/app/globals.css) 与现有主题预设的语义 token；不要为普通组件单独硬编码一套配色。图表等领域配色确有需要时说明语义并兼顾深浅主题。
- 间距、字号、按钮尺寸沿用组件变体和相邻页面，不为单页建立独立尺度。图标优先使用已有图标库，图标按钮提供可访问名称。
- 保持键盘操作、可见焦点、表单标签和错误提示；状态不能只靠颜色区分。窄屏避免关键操作被遮挡，宽表格可使用已有横向滚动模式。
- 展示真实的加载、空、错误与成功状态。空列表应说明下一步操作；演示数据不得伪装成业务结果。
- 危险操作的提示写明对象与影响，沿用现有确认交互。提交中防止重复触发，完成后提供明确反馈。

## 文案、日志与说明

- 使用简洁、直接的中文，按钮优先采用具体动作词，如“保存”“同步”“重新导入”。避免笼统的“操作成功”掩盖实际结果。
- 错误文案说明发生了什么及可采取的下一步；必要时提供技术详情，避免把实现细节堆入主流程。
- 日志和用户提示不得泄露密码、令牌、完整敏感连接串或真实业务内容。示例使用明确占位值，不放个人机器路径。

## SPEC 与开发文档

- 正文使用中文，文件路径、代码标识和命令保留原样。标题直接说明内容，表格用于并列比较，流程用有序列表。
- 能力名和变更 ID 使用英文小写连字符，例如 `tool-library`、`add-tool-source-filter`。
- 需求描述可观察行为，使用“必须 / 不得 / 应 / 可以”区分约束强度；每项需求具有稳定 ID，不随标题变化重编号。
- 验收场景使用 GIVEN / WHEN / THEN（前提 / 操作 / 结果）；涉及失败或边界时分别写场景，不用“正常工作”代替具体结果。
- 需求不混入实现步骤；设计记录方案与取舍，任务记录执行项，验证记录事实。完成前不预勾任务，不把预期命令结果当作证据。
- 仓库内链接优先使用相对路径。引用通用规则时链接到本文件或 PROJECT.md，不复制段落；改变全局风格时集中更新此处及必要的工具配置。
