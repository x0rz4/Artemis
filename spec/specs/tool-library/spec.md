# 工具库与技能库

## 目的与边界

运行时武器库（工具）与技能包都以磁盘为真源：库根下的文件加 `manifest.json`，页面只负责导入、同步、上传、快照与回滚。工具的执行复用 Bash 底层，平台不为脚本、JAR 或原生二进制新增执行器分支；技能包仍由 norma 按 `SKILL.md` 加载，平台只决定扫描根与写入落点。

本规范只写已落地的行为。库的在线更新、基线安装与依赖自检在其它变更中推进，落地后再补规范。

## 需求

### TL-001：磁盘是工具库的唯一真源

工具库的真源是运行目录下的文件与清单：清单缺失时建立空骨架并继续启动，清单损坏时报错而不静默覆盖；写回采用临时文件加原子替换，并保留上一版备份。启动时建立库并输出自检摘要，失败不得阻断启动。

#### 场景：首次启动

- GIVEN：全新运行目录，没有 `data/tools`。
- WHEN：启动服务。
- THEN：生成库目录与空清单，服务继续启动，日志留下自检摘要。

### TL-002：清单到工具的导入是单向的

导入把清单条目写成 `tools` 表里 `kind=command` 的自定义工具行，重复导入幂等；与内置工具 key 撞名时拒绝并说明原因。反向不成立：在「系统 → 工具」里编辑工具不回写清单。

#### 场景：编辑自定义工具

- GIVEN：已从清单导入的工具。
- WHEN：在「系统 → 工具」修改它的绑定或说明。
- THEN：只改动数据库里的工具行，清单文件保持不变。

### TL-003：缺失与不符只告警不阻断

文件缺失、摘要不符、运行期未安装只在自检结果与启动日志里标出，不阻止启动，也不阻止其它条目导入。摘要状态必须区分已校验、不符、未钉摘要、缺失与跳过。

### TL-004：执行层零改动

脚本、原生二进制与 JAR 由命令模板包装：绝对路径（正斜杠）加 `{args}` 占位，`python3`/`node`/`php` 作为前缀解释器，`java` 走 `java -jar`。不可导入的情形（script 缺 runtime、dir 缺 entry、未知 runtime）必须在导入时报错并列出可用取值。

#### 场景：脚本条目缺 runtime

- GIVEN：清单里 `kind=script` 的条目没有 runtime。
- WHEN：导入该条目。
- THEN：该条目失败并给出可读原因，其它条目照常导入。

### TL-005：审计能看到真实命令

自定义 command 工具以自身 key 被调用，审计用的命令由拦截层的命令渲染器还原（模板带缓存过期时间，导入、上传、删除与同步后失效），并以 `_command` 合并进规则匹配的输入，不覆盖输入里已有的同名字段。

### TL-006：多源同步是并集

一个库可配置多个源：工具库支持 github 与 http，技能库另支持 git 整仓。同步是并集——本地独有的条目不因源里没有而被删，源里删掉的条目也不删本地文件；同名条目按源刷新版本、摘要、路径、类型与运行期等元数据。落地顺序必须是先文件、后清单。摘要未钉（`sha256` 为空）时默认拒绝安装，除非该源显式开启 `allow_unpinned`。源级失败只记录并继续下一个源，单条目失败不阻断其它条目。

#### 场景：源里删掉一个条目

- GIVEN：本地清单有条目 A 与 B，源里只剩 A。
- WHEN：执行同步。
- THEN：B 的条目与文件都保留，A 按源刷新元数据。

### TL-007：技能库的扫描根与写入落点

扫描根按优先级排列：程序旁的 `skills/`（可由环境变量覆盖）→ 库内 `uploaded` → git 型源的镜像目录；同名技能以靠前的根为准。新建、上传与同步落在 `uploaded`，不污染程序目录；写入路径必须走统一的落点计算，不在处理函数里手拼路径。

### TL-008：快照与回滚

同步、覆盖上传、删除文件、清源与回滚之前自动生成快照（内容为将被改动的目标加清单），最多保留固定份数。回滚语义是并集：只把快照里的内容放回去，不删快照之后新增的条目；回滚前再存一份 `pre-rollback:` 快照。工具回滚后按清单重新注册工具行。

#### 场景：回滚到上一份快照

- GIVEN：库里有同步前的快照，同步后又新增了一个条目。
- WHEN：执行回滚。
- THEN：快照里的文件与清单被放回，同步后新增的条目仍在，且产生了一份回滚前的快照。

### TL-009：写锁与冲突

每个库一把写锁：同步、上传、删除、保存源、删除源与回滚互斥，第二个请求得到冲突响应而不是排队。回滚额外要求库空闲（没有运行中的任务与进行中的写入），否则同样拒绝。只写数据库、不写磁盘的导入不在该锁范围内。

## 边界与待确认

- 源条目里显式写了 `agents`、`enabled` 等平台侧字段时以源为准（`server/toollib_sync.go` 的绑定覆盖），只有源缺省时才保留本地取值——这与「平台侧状态不是源能决定的」这一约束存在张力，需要固定下来。
- 自检对 Python 的口径与命令模板不一致：命令模板固定 `python3`（`server/toollib.go`），而自检会使用系统配置的解释器（`server/toollib_check.go`）；配置的解释器不在 PATH 时会出现"自检可用、执行失败"。
- 源白名单与重定向校验、摘要不符的拒绝、冲突响应的返回路径目前没有自动化测试；技能库整体缺少 Go 测试。
