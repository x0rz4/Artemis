# 自更新

## 目的与边界

正式发行版可以从 Artemis 自己的发布源升级：检查版本、下载本平台发布包、校验、暂存、换装，失败时回滚。本规范描述已落地的行为，发布源写死在代码里，不提供运行时配置项——更新源可配等于给任何能改配置的人一条远程代码执行通道。

容器部署不走这条路径：换装写的是容器可写层，`docker compose up -d` 重建容器就会退回镜像自带的版本，更新应由拉取新镜像完成。

## 需求

### SU-001：固定发布源

发布源必须是写死在 `selfupdate/github.go` 的 `Repo` 常量，取值为 `owner/repo` 形式。检查更新只请求该源的 GitHub 正式 Release 接口，升级链路中的每一跳（含重定向）都必须是 HTTPS 且主机在升级白名单内。发布包命名必须与打包脚本一致：`artemis-<版本，无 v 前缀>-<os>-<arch>.zip`，并随包提供 `SHA256SUMS`。换源必须同时修改 `Repo` 与白名单域名名单，并确认该源的资产命名与校验和口径。

#### 场景：发布源可用

- GIVEN：正式发行版，发布源已配置。
- WHEN：请求检查更新。
- THEN：请求发往 `https://api.github.com/repos/<Repo>/releases/latest`，地址通过白名单校验，响应中的 `repo` 字段即该发布源。

#### 场景：发布源写错

- GIVEN：`Repo` 被改成缺斜杠、带多余路径或指向非白名单域名的值。
- WHEN：运行 `selfupdate` 包测试。
- THEN：发布源相关测试失败并指出问题，不需要联网。

### SU-002：未配置发布源时拒绝联网

`Repo` 为空或仍是占位值 `TO_BE_SET` 时，检查更新必须立刻返回可读错误并停留在本地，不得向任何地址发起请求。该分支供尚未搭好发布链路的 fork 使用。

#### 场景：占位值未替换

- GIVEN：`Repo` 为空或为 `TO_BE_SET`。
- WHEN：检查更新。
- THEN：立即得到"更新源未配置"错误，不产生网络请求。

### SU-003：检查更新与版本比较

检查更新由服务端执行（只有服务端能访问发布源），返回当前版本、运行模式、当前平台对应的资产名、资产是否可用、是否有更新。查询结果默认缓存 30 分钟，失败结果缓存 2 分钟，显式检查可绕过缓存。当前版本不是纯净三段式版本号时不提供一键更新并给出原因；缺少当前平台发布包时如实标记资产不可用。

#### 场景：重复检查命中缓存

- GIVEN：刚刚查询过发布源。
- WHEN：未显式要求刷新时再次检查。
- THEN：返回缓存结果，不重复访问发布源；显式刷新则绕过缓存。

#### 场景：开发构建

- GIVEN：当前版本是 `dev` 或带 git describe 后缀。
- WHEN：检查更新或尝试执行更新。
- THEN：检查结果标记为不可比较并给出原因，更新请求被拒绝，不用正式版覆盖本地构建。

#### 场景：容器部署

- GIVEN：进程运行在容器内。
- WHEN：检查更新。
- THEN：运行模式为 `docker`，界面据此说明容器更新应走镜像重建。

### SU-004：下载校验、暂存与换装回滚

一键更新只接受同时提供本平台 zip 与 `SHA256SUMS` 的正式 Release：下载后比对 SHA256，解出可执行文件并冒烟测试，通过后暂存新版本与其校验和；进程随后退出，由守护脚本重新拉起，下次启动校验暂存件后换装，旧版本保留为可回滚备份。连续多次启动未能确认稳定则自动回滚，起不来的版本保留供排查；也支持主动退回上一版本。同一次升级不允许并发执行。

#### 场景：缺少校验和或摘要不符

- GIVEN：Release 没有 `SHA256SUMS`、清单未收录本平台包，或下载内容与清单摘要不一致。
- WHEN：执行更新。
- THEN：拒绝安装并报告原因，当前版本不被替换。

#### 场景：暂存与换装

- GIVEN：下载内容校验通过。
- WHEN：完成更新请求。
- THEN：解出的可执行文件通过冒烟测试后暂存，并写上升级标记；进程退出由守护脚本拉起，下次启动完成换装并把旧版本备份下来。

#### 场景：新版本起不来

- GIVEN：换装后的新版本连续多次启动都未能确认稳定。
- WHEN：达到尝试上限。
- THEN：自动回滚到备份版本，失败的版本保留为可排查文件，升级标记被清除。

#### 场景：主动回滚

- GIVEN：存在可回滚的备份版本。
- WHEN：请求回滚。
- THEN：备份版本冒烟通过才换回，换回后仍可再滚回去；没有备份时明确报错。

#### 场景：升级进行中重复触发

- GIVEN：已有一次升级在进行。
- WHEN：再次请求执行更新。
- THEN：拒绝并提示已在进行中，不让两个流程写同一个暂存文件。
