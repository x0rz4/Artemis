# 任务预算与收尾

## 目的与边界

为长跑任务设 token 与工具次数上限，用"预留—结算"的方式在模型调用前占额，额度耗尽后停止新增工作并让在跑工作收尾写回。预算是本地用量账本，不是供应商金额账单，也不代表对供应商侧花销的约束。

## 需求

### TB-001：预算按任务配置，缺省不限

预算按任务保存在数据库：token 上限、工具次数上限、两者的预留额度、已用量、预留中数量、未报告用量请求数与状态。没有预算行的任务一律放行；上限为 0 表示不限。调整预算时保留已累计用量，只重算状态；预留大于上限的配置被拒绝。

#### 场景：任务未配置预算

- GIVEN：任务没有预算行。
- WHEN：执行意图与工具调用。
- THEN：不做任何预留，全部放行。

### TB-002：保守预留与结算

每次模型请求前按请求体规模、输出上限与固定余量估算并预留；请求返回后按实际用量结算，实际超过预留时补记差额。未报告用量的请求按预留额计入已用并单独计数，便于事后识别偏差。进程重启时把游离的预留言记为已消耗，避免额度被长期占用。

#### 场景：并发预留不超额

- GIVEN：token 上限 100、预留 20，8 个请求各需 30。
- WHEN：并发发起预留。
- THEN：只有 3 个获准，其余按额度不足被拒。

### TB-003：额度耗尽的处理

预留失败即视为额度耗尽：该次模型调用直接失败且不重试，工具调用被拒并返回可读原因。任务随后进入收尾——先标记收尾中，向在跑工作注入收尾指令（收割结果、保存已有证据与未完成原因），等待忙态清空（有等待上限），仍未结束则暂停任务。

#### 场景：token 额度耗尽

- GIVEN：任务 token 预算已用尽。
- WHEN：worker 再次请求模型调用。
- THEN：调用失败、任务进入收尾、在跑工作收到收尾指令；等待超时后任务被暂停而不是标记失败。

### TB-004：工具次数与收尾豁免

普通工具受"上限减预留"约束，预留部分只给收尾阶段使用；收尾工具可以吃到硬上限。

### TB-005：无进展（空转）保护

最后一条模型回合既无正文也无工具调用时，不硬停，而是注入一次续跑指令让模型带着已有思考继续；连续达到上限后放行收场并记录。上限默认 2，可由模型重试策略里的"空响应重试"配置为指定值或关闭。已由其它钩子决定硬停、或已经要求过续跑时不叠加。

#### 场景：连续空转

- GIVEN：模型连续多个回合只思考、无正文与工具调用。
- WHEN：达到配置的续跑上限。
- THEN：不再注入续跑指令，本次运行放行收场并留下记录。

### TB-006：步数与运行时长上限

Agent 的步数上限与运行时长上限按 agent 配置。撞上步数上限或运行时长上限的意图归为 exhausted，供规划者判断"这个方向试过但没做完"；正常结束但没有任何写回的意图同样归为 exhausted，不当作已覆盖。

## 边界与待确认

- README 的"有限默认轮次"实际只对 worker 生效（默认 60 步），planner、mainagent 与聊天默认不限，且已有库不会被回填——文档口径与实际默认值需要统一。
- 预算耗尽后的收尾以"暂停"落库，取消原因表现为用户暂停，与活动流里"额度耗尽与任务失败分开记录"的说明不一致。
- 预算状态可能降级：token 耗尽写入 exhausted 后，再来一次普通工具调用会把状态改回收尾中，只有工具次数达到硬顶才会回到 exhausted。
- 预算耗尽导致的模型调用失败会把意图落为 blocked，与前端"预算耗尽"徽标语义不一致。
- 若任务级超时收尾已经先占用收尾标记，预算收尾整段跳过。
- 收尾轮数解析、预算收尾流程与终局规划尚无自动化测试覆盖。
