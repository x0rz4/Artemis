# 开发规范协作

## 目的与边界

为 Artemis 的开发助手和维护者提供一致、可追踪的规则入口。本规范描述仓库文档的协作约定，不表示存在自动执行这些规则的 CLI 或 CI 校验器。

## 需求

### DEV-001：统一开发入口

AGENTS.md 与 CLAUDE.md 必须引用同一套 SPEC 工作流、风格规范和项目约束，不得维护各自独立的开发流程。

#### 场景：从任一助手入口开始

- GIVEN：开发者从 AGENTS.md 或 CLAUDE.md 进入仓库。
- WHEN：按照入口中的阅读顺序打开规则。
- THEN：到达相同的 SPEC 索引、WORKFLOW.md、STYLE.md 和 PROJECT.md。

### DEV-002：规则集中维护

全局风格必须在 STYLE.md 维护；项目技术约束必须在 PROJECT.md 维护。能力规范与变更记录应引用适用通用规则。

#### 场景：调整通用界面风格

- GIVEN：某变更需要修改全局界面风格。
- WHEN：开发者记录并实施该变更。
- THEN：统一规则更新在 STYLE.md，入口文件继续引用该文档，不增加另一份风格规则。

### DEV-003：变更与现行规范区分

标准与重点变更必须按 WORKFLOW.md 记录、验证、同步规范并归档；轻量改动可以使用交付说明记录。未实现或未完成必要验证的预期行为不得被标记为现行已完成能力。

#### 场景：验证仍有阻塞

- GIVEN：标准变更已实现，但必需的验收尚未完成。
- WHEN：更新变更状态并交付进度。
- THEN：记录阻塞及未执行项，变更保持进行中，不归档为已完成能力。

#### 场景：验证与规范同步完成

- GIVEN：变更任务和必要验收已完成。
- WHEN：同步现行规范并归档变更。
- THEN：现行规范反映落地行为，历史记录保留目标、增量和验证证据。
