# 备份与恢复

## 目的与边界

备份以离线脚本形式提供：服务端只提供脚本下载与迁移状态查询，打包、加密、校验与恢复都在操作者机器上完成，因此流程要求先停应用与代理并显式确认。本规范描述脚本与接口的既定行为，不表示存在服务端编排、进度或审计。

## 需求

### BR-001：备份内容与凭据

备份包含数据库逻辑导出与运行数据目录，可选包含技能目录。模型与业务凭据随数据库导出进入包内；本地配置文件与 JWT 签名密钥默认不进包，只有显式提供路径时才包含并在清单里标明。口令只从环境变量读取，不落命令行、不回显。包路径必须显式指定、不得位于源目录内、已存在即拒绝，结束后输出包摘要。

#### 场景：不带本地凭据的备份

- GIVEN：未指定本地凭据路径。
- WHEN：执行备份。
- THEN：包内只有数据库导出与数据目录，清单标明本地凭据未包含。

### BR-002：加密与完整性

整包按分块对称加密，密钥由口令经密钥派生函数生成，每包独立随机盐并有明确的最小口令长度。格式带魔数与版本号；校验清单、路径白名单、条目数与逐文件摘要，总量有上限，任何不符即拒绝。

### BR-003：恢复隔离

恢复只能落到新的空数据库与不存在的目标目录：目标目录已存在、目标库已有关系、缺少独立连接串或未确认离线都会拒绝。文件先落临时目录再整体移动；数据库恢复在单个事务内完成。恢复完成后由操作者人工切换连接串与数据目录，应用自身不读恢复脚本的参数。

#### 场景：目标库非空

- GIVEN：目标数据库已存在任何表。
- WHEN：执行恢复。
- THEN：拒绝恢复，不改动目标库与目标目录。

### BR-004：一致性由操作者声明

脚本无法验证应用与录制代理确实已停止，备份与恢复都要求显式确认离线；备份过程中检测到文件被改动、或遇到链接与重解析点时会报错，并保证失败时不产出最终包。

### BR-005：迁移状态可见

应用启动时按顺序执行幂等迁移：一次性标记加咨询锁保证只执行一次，失败不写标记以便下次启动重试，成功则记录 ready。接口与设置页展示每项迁移的状态、错误与更新时间。

## 边界与待确认

- 恢复后默认没有 JWT 签名密钥，需要重新登录；密钥位置在容器与本地不同，容易漏备。
- 运行数据目录与技能目录由人工传入且不写入清单，传错目录仍会报告成功。
- 清单里的 schema 摘要常态是"不可用"，恢复端也不比对 schema 版本，跨版本恢复没有兼容性校验。
- 数据库已恢复但目标目录校验失败时，只保留临时目录并告警，没有回滚。
- 脚本、脚本下载接口、迁移状态接口与两个前端面板都没有自动化测试。
- 备份包扩展名未被忽略规则覆盖，存在被误提交的风险。
- 脚本使用独立的环境变量前缀（`ARTEMIS_*`），与仓库其余 `ARTEX_*` 约定不一致，需要统一或说明理由。
