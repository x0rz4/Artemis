# unify-spec-workflow：统一 Artemis 开发规范

- 状态：archived
- 类型：标准
- 关联能力：development（新增）

## 目标与范围

原仓库仅 AGENTS.md 记录开发约束，缺少共用工作流、风格文档和 Claude 入口。本次建立参考 OpenSpec 的定制 Markdown 规范体系，将风格集中维护，使两个助手入口遵循同一流程。

范围包括 SPEC 索引、工作流、风格、原项目约束迁移、模板、协作能力规范与 README 导航。不修改业务代码、不引入 OpenSpec CLI 或自动化校验依赖。

## 需求增量

### ADDED：DEV-001 统一开发入口

AGENTS.md 和 CLAUDE.md 必须引用同一套工作流、风格与项目约束。

- GIVEN：从任一助手入口开始。
- WHEN：读取入口引用。
- THEN：阅读顺序和规则目标完全一致。

### ADDED：DEV-002 规则集中维护

全局风格集中到 STYLE.md，项目约束集中到 PROJECT.md；迁移不得丢失原有技术约定。

- GIVEN：原 AGENTS.md 中的架构与构建约束。
- WHEN：拆分规则文档。
- THEN：技术约束完整保留，命名风格转入统一风格文档。

### ADDED：DEV-003 变更与现行规范区分

工作流必须规定分级、需求与验收、实现、验证、同步与归档；未完成验证不得归档为已完成能力。

- GIVEN：标准变更的必要验收尚未完成。
- WHEN：准备交付。
- THEN：保留进行中状态并说明阻塞，不把预期行为登记为已完成。

## 设计与影响

- 使用可纳入 Git 的 `spec/` 目录，保留现有 `/docs/` 忽略策略。
- 将 OpenSpec 的提案、需求增量、设计、任务与验证合并到 `change.md`，降低维护成本。
- 两个入口保持相同短文，只引用规则。原开发指南迁至 PROJECT.md，命名规则转入 STYLE.md。
- 轻量变更允许交付说明；涉及接口、数据、鉴权、同步与发布等影响时升级记录要求。
- 仅文档，无 API、数据库迁移与运行行为影响；恢复时可依据 Git 差异还原文档布局。
